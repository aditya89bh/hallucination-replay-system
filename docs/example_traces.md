# Example Trace Catalog

This catalog lists the example and benchmark traces included with the repository. The examples are deterministic fixtures for demos, tests, and local release validation; they are not intended to represent private production data.

## Supported example categories

| Category | Location | Purpose |
| --- | --- | --- |
| Hallucination benchmarks | `benchmarks/hallucination/` | Deterministic unsupported, contradiction, partial-support, and full-support cases |
| Replay benchmark | `benchmarks/replay_benchmark.py` | Synthetic replay workload for timeline and navigation timing |
| Storage benchmark | `benchmarks/storage_benchmark.py` | Synthetic storage workload for repository operations |
| Comparison benchmark | `benchmarks/comparison/` | Deterministic comparison workload and summary output |
| Diffing examples | `examples/diffing/` | JSON fixtures for successful/failed, retrieval regression, and memory regression scenarios |
| Reconstruction examples | `examples/reconstruction/` | Markdown examples showing reconstructed state outputs |

## Hallucination benchmark traces

### `benchmarks/hallucination/unsupported_claim.json`

A trace where the agent output includes a claim that is not supported by available evidence. Use this fixture to exercise unsupported-claim detection and severity scoring.

### `benchmarks/hallucination/contradiction.json`

A trace where the agent output conflicts with available evidence. Use this fixture to exercise contradiction detection and report generation.

### `benchmarks/hallucination/partially_supported_claim.json`

A trace where some output claims are supported and others are missing sufficient evidence. Use this fixture to verify partial coverage behavior and threshold interpretation.

### `benchmarks/hallucination/fully_supported_claim.json`

A trace where the agent output is supported by available evidence. Use this fixture as a low-risk control case for hallucination scoring.

Run the benchmark evaluation with:

```bash
pytest tests/test_hallucination_evaluation.py
```

## Replay examples

Replay examples are generated by tests and benchmark helpers rather than stored as a large static trace catalog. The replay benchmark builds deterministic synthetic traces and measures replay loading, navigation, snapshots, checkpoints, and timeline export.

Run it with:

```bash
python benchmarks/replay_benchmark.py
```

For API replay examples, see [API usage examples](api_examples.md). For CLI replay examples, see [CLI reference](cli_reference.md).

## Comparison examples

### `examples/diffing/successful_vs_failed.json`

A comparison fixture for analyzing differences between a successful execution and a failed execution.

### `examples/diffing/retrieval_regression.json`

A comparison fixture focused on retrieval changes that can cause downstream answer quality regressions.

### `examples/diffing/memory_regression.json`

A comparison fixture focused on memory state changes that can affect agent decisions.

Run comparison benchmark output with:

```bash
python benchmarks/comparison/comparison_benchmark.py
cat benchmarks/comparison/summary.json
```

## Reconstruction examples

The reconstruction examples under `examples/reconstruction/` show expected report-style output for:

- full state reconstruction;
- memory reconstruction;
- tool reconstruction.

Use these documents to understand the shape of reconstructed state before integrating the reconstruction APIs into your own debugging workflow.

## Selecting a trace for a demo

- Use `fully_supported_claim.json` to show a clean/control hallucination result.
- Use `unsupported_claim.json` to show unsupported claim detection.
- Use `contradiction.json` to show contradiction detection.
- Use `partially_supported_claim.json` to discuss threshold behavior and evidence coverage.
- Use the diffing examples to show comparison reports and regression analysis.

## Privacy note

Example traces are safe deterministic fixtures. Before creating your own example traces from production data, redact secrets, customer data, private prompts, private retrieval content, and sensitive tool outputs.
